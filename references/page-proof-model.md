# Page Proof Model

Every slide is a proof unit.

## Page Contract

Each slide should specify:

```text
Management question:
Claim:
Primary proof object:
Supporting evidence:
Implication/action:
Source and scope:
```

## Proof Object Types

| Proof object | Use when |
|---|---|
| KPI strip | The page must establish status quickly |
| Trend chart | Movement over time proves the claim |
| Slope chart | Before/after change is the message |
| Variance bridge | A gap must be decomposed |
| Profit bridge | Earnings pressure must be explained |
| Cost bridge | Cost disadvantage must be decomposed |
| Timeline | Sequence and project history matter |
| Ledger table | Status, responsibility, or compliance must be tracked |
| Decision matrix | A choice among options must be defended |
| Issue tree | Root cause structure must be shown |
| Causal chain | One event leads to another |
| 2x2 matrix | Segmentation or policy boundary is needed |
| Roadmap | Future actions need sequencing |
| Dense comparison table | Options, benchmarks, or trade-offs must be compared |

## Page Title Rules

- Use a conclusion sentence.
- Avoid generic nouns.
- Prefer 14-28 Chinese characters or a concise English claim.
- Title must match the proof object.

## Slide Density

A strong page usually has:

- one conclusion title
- one main proof object
- two to four highlighted facts
- a short explanation chain
- an implication, decision, or action
- source and scope note

High density is not the same as clutter. The page must still have clear hierarchy.
